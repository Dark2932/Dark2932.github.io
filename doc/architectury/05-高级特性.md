# 高级特性

本文档介绍 Architectury 的高级特性，适用于 Minecraft 1.21.1 版本。

> 💡 **提示**：这些特性适合有一定基础后再学习。如果你是新手，建议先掌握 [API 核心功能](./03-API核心功能.md) 后再来看这部分。

## Mixin 集成

### 什么是 Mixin？

**一句话解释**：Mixin 让你"偷偷修改"Minecraft 的代码，而不用直接改它的源文件。

**生活化比喻**：

```
Minecraft 的代码就像一栋大楼，你没有大楼的钥匙（源代码）。
但 Mixin 让你可以：
  - 在某个房间的门打开时偷偷塞一张传单进去（注入代码）
  - 把某个房间的灯换成更亮的（修改行为）
  - 在走廊尽头加一个新路标（添加逻辑）

你不需要拆掉大楼重建，只需要在关键时刻"动手脚"。
```

### Mixin 配置文件

Mixin 需要一个配置文件来告诉游戏"我要修改哪些类"：

**common/src/main/resources/yourmod.common.mixins.json**：

```json
{
  "required": true,
  "package": "com.yourname.yourmod.mixin",
  "compatibilityLevel": "JAVA_17",
  "mixins": [
    "common/ExampleMixin"           ← 服务器端和客户端都生效的 Mixin
  ],
  "client": [
    "client/ExampleClientMixin"     ← 仅客户端生效的 Mixin
  ]
}
```

**通俗理解**：这个 JSON 文件就像一份"改造申请表"，告诉游戏"我要动哪些地方"。

### 最常见的 Mixin 用法：@Inject

`@Inject` 就像在方法的某个位置"插入一段自己的代码"：

```java
@Mixin(Player.class)  // 目标：修改 Player 类
public abstract class ExampleMixin {
    
    // 在 tick() 方法的开头（HEAD）插入代码
    @Inject(method = "tick", at = @At("HEAD"))
    private void onTick(CallbackInfo ci) {
        Player player = (Player) (Object) this;
        // 这段代码会在玩家每 tick 执行时运行
    }
}
```

**注入位置说明**：

```
方法执行流程：
  HEAD → 方法体开始执行
         ... 原始代码执行 ...
  RETURN → 方法准备返回
  TAIL → 方法执行完毕
  
你可以选择在哪个位置插入你的代码。
```

### 常见 Mixin 例子

#### 让玩家不再受摔落伤害

```java
@Mixin(Player.class)
public abstract class NoFallDamageMixin {
    // 修改 getHealth() 的返回值
    @Inject(method = "hurt", at = @At("HEAD"), cancellable = true)
    private void preventFallDamage(DamageSource source, float amount, CallbackInfoReturnable<Boolean> cir) {
        if (source.is(DamageTypes.FALL)) {
            cir.setReturnValue(false);  // 返回 false，表示"没有受到伤害"
        }
    }
}
```

#### 每 tick 给玩家加分

```java
@Mixin(Player.class)
public abstract class ScoreMixin {
    @Shadow
    private int score;  // 访问 Player 类的私有字段
    
    @Inject(method = "tick", at = @At("HEAD"))
    private void addScore(CallbackInfo ci) {
        this.score += 1;  // 每 tick 增加 1 分
    }
}
```

### @Shadow - 访问私有字段

有时候你需要读取或修改目标类的私有字段，这时用 `@Shadow`：

```java
@Mixin(Player.class)
public abstract class ExampleMixin {
    @Shadow
    private int inventoryMenu;  // 这个字段名必须和目标类中的一样
    
    // 现在你可以在其他方法中使用 this.inventoryMenu 了
}
```

**通俗理解**：`@Shadow` 就像拿到了私有字段的"备用钥匙"。

## 访问转换器 (Access Transformers)

### 什么是访问转换器？

**一句话解释**：Minecraft 有些代码是"上锁的"（private），访问转换器帮你"开锁"。

**生活化比喻**：

```
Minecraft 的代码里有一些"私密房间"（private 字段/方法），你进不去。
Access Transformer 就像一把万能钥匙，帮你把这些房间的锁打开。
```

### 如何使用

**在 Loom 中配置**（build.gradle）：

```groovy
loom {
    accessWidenerPath = file("src/main/resources/yourmod.accesswidener")
}
```

**yourmod.accesswidener 文件**：

```
accessWidener v2 named

# 把某个私有方法变成公开的
accessible method net/minecraft/world/entity/Player somePrivateMethod ()V

# 把某个私有字段变成公开的
accessible field net/minecraft/world/level/block/BlockEntity somePrivateField I
```

**通俗理解**：这个文件就是你的"开锁清单"，列出你想打开的所有"锁"。

## 数据生成 (Data Generation)

### 什么是数据生成？

**一句话解释**：用 Java 代码自动生成 JSON 文件（配方、战利品表、标签等），而不是手动写。

**生活化比喻**：

```
手动写 JSON = 手写每一张菜单（容易写错，难维护）
数据生成 = 用打印机自动打印菜单（精确，易维护）

数据生成器就像一个"自动菜单生成系统"，你只需要告诉它规则。
```

### 生成配方

```java
public class ModRecipeProvider extends RecipeProvider {
    @Override
    protected void registerRecipes() {
        // 有序配方（像工作台放物品的位置有讲究）
        // 对应 JSON: {"pattern": ["###", "# #", "###"], "key": {"#": "stone"}}
        ShapedRecipeBuilder.shaped(RecipeCategory.MISC, ModItems.RUBY.get())
            .pattern("###")     // 第一行：三个石头
            .pattern("# #")     // 第二行：石头 空 石头
            .pattern("###")     // 第三行：三个石头
            .define('#', Items.STONE)  // # 代表石头
            .unlockedBy("has_stone", has(Items.STONE))  // 解锁条件
            .save(this);
        
        // 无序配方（物品随便放）
        ShapelessRecipeBuilder.shapeless(RecipeCategory.MISC, ModItems.RUBY.get())
            .requires(Items.REDSTONE)  // 需要一个红石
            .requires(Items.DIAMOND)   // 需要一个钻石
            .unlockedBy("has_diamond", has(Items.DIAMOND))
            .save(this);
    }
}
```

### 生成标签

```java
public class ModBlockTagsProvider extends BlockTagsProvider {
    @Override
    protected void registerTags() {
        // 把你的方块加入"可用镐挖掘"标签
        tag(BlockTags.MINEABLE_WITH_PICKAXE)
            .add(ModBlocks.RUBY_BLOCK.get());
        
        // 把你的方块加入"需要铁镐"标签
        tag(BlockTags.NEEDS_IRON_TOOL)
            .add(ModBlocks.RUBY_BLOCK.get());
    }

```

### 生成战利品表（方块掉落物）

```java
public class ModLootTableProvider extends BlockLootSubProvider {
    @Override
    protected void generate() {
        // 方块破坏后掉落自身（像石头掉落圆石）
        dropSelf(ModBlocks.RUBY_BLOCK.get());
        
        // 方块破坏后掉落指定物品
        add(ModBlocks.RUBY_ORE.get(), 
            createSingleItemTable(ModItems.RUBY.get()));
    }
}
```

## 事件高级用法

### 事件优先级

当多个模组同时监听同一个事件时，优先级决定谁先执行：

```java
EntityEvent.LIVING_HURT.register(new EventConsumer<>() {
    @Override
    public EventResult handle(LivingEntity entity, DamageSource source, float amount) {
        // 我的代码先执行（高优先级）
        return EventResult.pass();
    }
    
    @Override
    public int getPriority() {
        return EventPriority.HIGH;  // 高优先级
    }
});
```

**优先级顺序**（从先到后）：
```
HIGHEST → HIGH → NORMAL → LOW → LOWEST
先执行                                    后执行
```

**通俗理解**：就像医院的急诊分级，危重病人（HIGH）先看，小感冒（LOW）后看。

## 网络高级用法

### 数据包验证（安全！）

**永远不要信任客户端发来的数据**，一定要验证：

```java
NetworkManager.registerReceiver(NetworkManager.Side.C2S, PACKET_ID, (buf, context) -> {
    // 1. 检查数据包大小（防止恶意超大数据包）
    if (buf.readableBytes() > 1024) {
        return;  // 丢弃
    }
    
    // 2. 检查玩家权限
    if (!context.getPlayer().hasPermissions(2)) {
        return;  // 没权限就忽略
    }
    
    // 3. 验证数据合理性
    BlockPos pos = buf.readBlockPos();
    if (pos.getY() < -64 || pos.getY() > 320) {
        return;  // 坐标不合理，丢弃
    }
    
    // 4. 在主线程安全执行
    context.queue(() -> {
        // 安全地修改世界
    });
});
```

**通俗理解**：就像餐厅收到外卖订单，要先检查"这个订单是不是真的"、"有没有付钱"、"地址合不合理"。

### context.queue() - 线程安全

```java
// ❌ 危险：网络回调可能在非主线程执行
NetworkManager.registerReceiver(Side.C2S, PACKET_ID, (buf, context) -> {
    level.setBlockAndUpdate(pos, state);  // 可能崩溃！
});

// ✅ 安全：用 queue() 确保在主线程执行
NetworkManager.registerReceiver(Side.C2S, PACKET_ID, (buf, context) -> {
    context.queue(() -> {
        level.setBlockAndUpdate(pos, state);  // 安全！
    });
});
```

**为什么？** 网络数据包的处理可能在"后台线程"执行，但修改游戏世界必须在"主线程"。`context.queue()` 就像"排队等主线程处理"。

## 模组内嵌库

### 什么是内嵌库？

把第三方库打包进你的模组 jar 文件里，这样用户不需要单独安装这些库。

```groovy
dependencies {
    implementation 'com.google.code.gson:gson:2.10.1'  // 引入库
    include 'com.google.code.gson:gson:2.10.1'          // 打包进模组 jar
}
```

**通俗理解**：
- `implementation` = "我需要用这个库"
- `include` = "把这个库装进我的行李箱一起带走"

### 常见问题排查

| 问题 | 可能原因 | 解决方法 |
|------|----------|----------|
| Mixin 失败 | 方法名写错了 | 检查映射，确认方法名正确 |
| 注册顺序错误 | 静态初始化问题 | 使用 DeferredRegister |
| 平台代码不生效 | 包名或类名不对 | 检查命名规则 |
| 映射不匹配 | 各模块映射不同 | 确保统一使用相同映射 |
