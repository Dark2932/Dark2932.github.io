# 环境配置详解

本文档详细介绍 Architectury 项目的环境配置，适用于 Minecraft 1.21.1 版本。

> 💡 **阅读建议**：如果你是新手，建议先看 [入门指南](./01-入门指南.md) 了解整体概念，再来看这个文档的细节。

## 项目生成器配置

访问 [https://generate.architectury.dev](https://generate.architectury.dev/) 进行项目生成：

### 基本配置

| 配置项 | 说明 | 推荐值 |
|--------|------|--------|
| Minecraft Version | Minecraft 版本 | 1.21.1 |
| Mod Loader | 目标平台 | Fabric, Forge, NeoForge |
| Architectury API | 是否包含 API | 是（推荐） |
| Use Parchment | 使用 ParchmentMC 映射 | 是（推荐） |

### 包名配置

- **Group ID**：你的域名反转，如 `com.yourname`
- **Artifact ID**：模组 ID，如 `yourmod`
- **Package Name**：Java 包名，如 `com.yourname.yourmod`

## 手动配置详解

### 1. settings.gradle - "项目有哪些部分组成"

**通俗理解**：这个文件就像餐厅的"分店清单"，告诉 Gradle 你的项目由哪些子项目组成。

```groovy
pluginManagement {
    repositories {
        // 以下是 Gradle 去哪里下载插件的"仓库地址"
        // 就像你去不同的商店买东西
        
        maven { url = 'https://maven.architectury.dev/' }      // Architectury 插件的"专卖店"
        maven { url = 'https://maven.fabricmc.net/' }           // Fabric 相关插件的"专卖店"
        maven { url = 'https://maven.neoforged.net/releases/' } // NeoForge 相关插件的"专卖店"
        gradlePluginPortal()                                    // Gradle 官方插件市场（像应用商店）
        mavenCentral()                                          // Java 最大的公共仓库（像淘宝）
    }
}

// 告诉 Gradle：我的项目有这 4 个子项目
// 就像说：我的连锁餐厅有总部、北京店、上海店、广州店
include('common', 'fabric', 'forge', 'neoforge')
```

**实际场景**：当你运行 `./gradlew build` 时，Gradle 会依次构建这 4 个子项目。

### 2. 根 build.gradle - "全局配置"

**通俗理解**：这个文件就像"连锁餐厅总部的操作手册"，规定了所有分店都要遵守的规则。

```groovy
plugins {
    // ==================== 插件声明 ====================
    
    // Architectury 插件：让多平台开发成为可能的核心工具
    // 就像连锁餐厅的"标准化管理系统"
    id "architectury-plugin" version "3.4-SNAPSHOT"
    
    // Loom 插件：Minecraft 模组开发的构建工具
    // apply false 表示"先下载但不启用"，让子项目自己决定用不用
    // 就像"厨房设备采购清单"，先列出来，等各分店自己决定要不要用
    id "dev.architectury.loom" version "1.7-SNAPSHOT" apply false
    
    // Quiltflower 反编译器：让代码更易读（可选）
    // '1.+' 表示自动使用最新版本
    id 'io.github.juuxel.loom-quiltflower' version '1.+' apply false
}

// ==================== Architectury 全局配置 ====================
architectury {
    // 告诉 Architectury：我们要为 Minecraft 1.21.1 开发
    // rootProject.minecraft_version 是从 gradle.properties 读取的
    minecraft = rootProject.minecraft_version
}

// ==================== 子项目统一配置 ====================
// 这部分配置会应用到 common、fabric、forge、neoforge 所有子项目
subprojects {
    // 应用插件：每个子项目都需要这些插件
    apply plugin: "java"                  // Java 语言支持（必须）
    apply plugin: "architectury-plugin"   // Architectury 支持（必须）
    apply plugin: "maven-publish"         // Maven 发布支持（可选，用于发布到 Maven 仓库）
    
    // 项目信息：从 gradle.properties 读取
    version = rootProject.mod_version      // 模组版本，如 "1.0.0"
    group = rootProject.maven_group        // 组织名，如 "com.yourname"
    
    // ==================== 仓库配置 ====================
    // repositories 告诉 Gradle 去哪里下载依赖库
    repositories {
        maven { 
            name = 'ParchmentMC'  // 给这个仓库起个名字（方便引用）
            url = 'https://maven.parchmentmc.org'  // ParchmentMC 映射库的地址
        }
        // 注意：Minecraft 和 Fabric/Forge 的仓库由 Loom 自动添加，不需要手动配置
    }
    
    // ==================== 依赖配置 ====================
    dependencies {
        // Minecraft 本体 - 这是必须的
        // ${rootProject.minecraft_version} 会替换为 gradle.properties 中的版本号
        minecraft "com.mojang:minecraft:${rootProject.minecraft_version}"
        
        // 映射文件：把 Minecraft 的混淆代码翻译成可读的名字
        // officialMojangMappings() = 使用 Mojang 官方映射（推荐）
        mappings loom.officialMojangMappings()
        
        // 【可选】使用 ParchmentMC 映射（提供更好的参数名）
        // parchment 就像在官方映射基础上加了"注释"，让代码更易读
        // mappings loom.layered() {
        //     officialMojangMappings()
        //     parchment("org.parchmentmc.data:parchment-${rootProject.minecraft_version}:2024.11.17@zip")
        // }
    }
}
```

**配置文件读取顺序**：
1. Gradle 先读取 `settings.gradle` 知道有哪些子项目
2. 然后读取根 `build.gradle` 的全局配置
3. 最后读取各子项目的 `build.gradle`

### 3. gradle.properties - "配置常量"

**通俗理解**：这个文件就像"餐厅的配置表"，把所有可变的值集中管理。改版本号时只需要改这一个地方。

```properties
# ==================== 版本配置 ====================
# 这些变量会被 build.gradle 中的 ${} 语法引用

minecraft_version=1.21.1                    # Minecraft 版本
minecraft_version_range=[1.21.1,1.22)       # 兼容的版本范围（方括号=包含，圆括号=不包含）
                                            # [1.21.1,1.22) 表示 1.21.1 到 1.22 之间（不含 1.22）

fabric_version=0.16.0                       # Fabric API 版本
fabric_loader_version=0.16.9                # Fabric Loader 版本（加载模组的工具）
forge_version=52.0.16                       # Forge 版本
neoforge_version=21.1.77                    # NeoForge 版本

# ==================== 模组信息 ====================
mod_version=1.0.0                           # 你的模组版本号
maven_group=com.yourname                    # Maven 组织名（通常是域名反转）
archives_base_name=yourmod                  # 构建产物的基础文件名

# ==================== Architectury 配置 ====================
architectury_version=14.0.3                 # Architectury API 版本

# ==================== 平台配置 ====================
# 指定要构建哪些平台（用逗号分隔）
enabled_platforms=fabric,forge,neoforge
```

**实际场景**：
- 当 Minecraft 更新时，只需修改 `minecraft_version`
- 当你发布新版本时，只需修改 `mod_version`
- 如果你不想支持某个平台，从 `enabled_platforms` 中删除它

### 4. Common 模块配置 - "总部的配置"

**通俗理解**：Common 模块是你的"研发总部"，存放所有跨平台共享的代码。

```groovy
plugins {
    id "dev.architectury.loom"  // 启用 Loom 插件（Minecraft 开发必备）
}

// Loom 的一些设置
loom {
    silentMojangMappingsLicense()  // 静默 Mojang 映射的许可提示
    // 每次构建时会弹出"你同意 Mojang 的映射使用条款吗？"
    // 加了这行就不再弹出了（你已经默认同意了）
}

// ==================== 依赖配置 ====================
dependencies {
    // Minecraft 本体
    minecraft "com.mojang:minecraft:${rootProject.minecraft_version}"
    
    // 映射文件
    mappings loom.officialMojangMappings()
    
    // Fabric Loader - 仅在编译时需要
    // compileOnly 表示"编译代码时需要它，但打包时不要包含它"
    // 为什么？因为运行时 Fabric 平台会自己提供这个
    compileOnly "net.fabricmc:fabric-loader:${rootProject.fabric_loader_version}"
    
    // Architectury API
    // modImplementation 表示"这是一个模组依赖，需要特殊处理"
    modImplementation "dev.architectury:architectury:${rootProject.architectury_version}"
}

// ==================== Architectury 平台配置 ====================
architectury {
    // 告诉 Architectury：这个模块是"公共模块"
    // rootProject.enabled_platforms.split(",") 把 "fabric,forge,neoforge" 分割成数组
    common(rootProject.enabled_platforms.split(","))
}
```

**为什么要用 compileOnly？**
```
Common 模块的代码会在 Fabric、Forge、NeoForge 上运行
但 Fabric Loader 只在 Fabric 平台存在
所以不能把 Fabric Loader 打包进 Common 模块
只能在编译时用一下，运行时由各平台自己提供
```

### 5. Fabric 模块配置 - "北京分店的配置"

**通俗理解**：Fabric 模块是"北京分店"，只负责 Fabric 平台特有的代码。

```groovy
plugins {
    id "dev.architectury.loom"
}

dependencies {
    // Minecraft 本体
    minecraft "com.mojang:minecraft:${rootProject.minecraft_version}"
    mappings loom.officialMojangMappings()
    
    // Fabric Loader - 这次用 modImplementation
    // 因为 Fabric 模块只在 Fabric 平台运行，所以可以打包进去
    modImplementation "net.fabricmc:fabric-loader:${rootProject.fabric_loader_version}"
    
    // Fabric API - Fabric 平台的扩展 API
    modImplementation "net.fabricmc.fabric-api:fabric-api:${rootProject.fabric_version}"
    
    // Architectury API
    modImplementation "dev.architectury:architectury:${rootProject.architectury_version}"
    
    // ==================== 引用 Common 模块 ====================
    // 这是关键！让 Fabric 模块可以使用 Common 模块的代码
    
    // 引用 Common 模块的代码（编译时和运行时）
    implementation project(path: ':common', configuration: 'namedElements')
    
    // 转换 Common 模块的代码（生产环境打包时用）
    // transformProductionFabric 会把 Common 代码转换成 Fabric 兼容的格式
    runtimeOnly(project(path: ':common', configuration: 'transformProductionFabric'))
    compileOnly(project(path: ':common', configuration: 'transformProductionFabric'))
}

// ==================== Architectury 平台配置 ====================
architectury {
    // 告诉 Loom 这是一个平台模块（会生成 IDE 运行配置）
    platformSetupLoomIde()
    
    // 告诉 Architectury：这个模块是 Fabric 平台
    fabric()
}
```

**namedElements vs transformProductionFabric**：
```
namedElements = Common 模块的"原始代码"（用命名映射的）
transformProductionFabric = Common 模块的"转换后代码"（Fabric 兼容的）

开发时用 namedElements（方便调试）
打包时用 transformProductionFabric（确保兼容性）
```

### 6. Forge 模块配置 - "上海分店的配置"

**通俗理解**：Forge 模块是"上海分店"，只负责 Forge 平台特有的代码。

```groovy
plugins {
    id "dev.architectury.loom"
}

dependencies {
    // Minecraft 本体
    minecraft "com.mojang:minecraft:${rootProject.minecraft_version}"
    mappings loom.officialMojangMappings()
    
    // Forge - 用 forge 而不是 modImplementation
    // forge 是 Loom 专门为 Forge 准备的配置
    forge "net.minecraftforge:forge:${rootProject.forge_version}"
    
    // Architectury API
    modImplementation "dev.architectury:architectury:${rootProject.architectury_version}"
    
    // ==================== 引用 Common 模块 ====================
    implementation project(path: ':common', configuration: 'namedElements')
    
    // 转换 Common 模块的代码（Forge 版本）
    runtimeOnly(project(path: ':common', configuration: 'transformProductionForge'))
    compileOnly(project(path: ':common', configuration: 'transformProductionForge'))
}

architectury {
    platformSetupLoomIde()
    
    // 告诉 Architectury：这个模块是 Forge 平台
    forge()
}
```

**Forge 和 Fabric 的配置差异**：
```
Fabric：用 modImplementation 引入 Fabric Loader 和 Fabric API
Forge：用 forge 引入 Forge（Loom 会自动处理）

这是因为 Forge 和 Fabric 的加载机制不同，Loom 帮你处理了这些差异。
```

## 依赖配置详解

### 依赖配置类型

**通俗理解**：依赖配置就像"购物清单上的备注"，告诉 Gradle 这个东西什么时候用。

| 配置 | 编译时 | 运行时 | 传递性 | 通俗解释 | 使用场景 |
|------|--------|--------|--------|----------|----------|
| `implementation` | ✔ | ✔ | ❌ | "我需要，但不告诉别人" | 最常用的依赖方式 |
| `api` | ✔ | ✔ | ✔ | "我需要，也让别人用" | 你的模组提供的 API |
| `compileOnly` | ✔ | ❌ | ❌ | "写代码时参考，打包不要" | 平台加载器、注解处理器 |
| `compileOnlyApi` | ✔ | ❌ | ✔ | "写代码时参考，也让别人参考" | 某些 API jar |
| `runtimeOnly` | ❌ | ✔ | ❌ | "打包进去，但写代码用不到" | 驱动程序、运行时库 |
| `localRuntime` | ❌ | ✔ | ❌ | "本地运行需要，发布不要" | 本地测试工具 |

**什么是"传递性"？**
```
如果你的模组 A 依赖了库 B（用 api）：
  → 其他模组 C 依赖你的模组 A 时，也能用库 B 的代码

如果你的模组 A 依赖了库 B（用 implementation）：
  → 其他模组 C 依赖你的模组 A 时，不能用库 B 的代码
```

### 模组依赖 - "加 mod 前缀"

**通俗理解**：模组依赖就像"特殊商品"，需要特殊处理（重映射）。

```groovy
dependencies {
    // 普通 Java 库
    implementation 'com.google.code.gson:gson:2.10.1'
    
    // 模组依赖（加 mod 前缀）
    // modImplementation = implementation 的"模组版本"
    // Loom 会自动把模组的代码从一种映射翻译成你项目使用的映射
    modImplementation "net.fabricmc.fabric-api:fabric-api:${fabric_version}"
    
    // 模组 API 依赖
    modApi "dev.architectury:architectury:${architectury_version}"
    
    // 模组仅编译依赖
    modCompileOnly "some:mod:1.0.0"
    
    // 模组仅运行依赖
    modRuntimeOnly "some:mod:1.0.0"
}
```

**为什么要加 mod 前缀？**
```
普通 Java 库：代码是固定的，不需要翻译
Minecraft 模组：代码是用某种映射写的（如 SRG、Yarn）
  → 如果你的项目用 Mojang 映射，模组的代码需要"翻译"成 Mojang 映射
  → mod 前缀告诉 Loom "这个依赖需要重映射"
```

### 库依赖 - "普通商品"

```groovy
dependencies {
    // 普通 Java 库（不需要重映射）
    implementation 'com.google.code.gson:gson:2.10.1'
    
    // Forge 特殊配置
    // Forge 平台需要手动把非模组库加到运行时路径
    // 就像告诉 Forge "这个库是我的原料，运行时要用"
    forgeRuntimeLibrary 'com.google.code.gson:gson:2.10.1'
}
```

### 包含库 - "装进我的行李箱"

```groovy
dependencies {
    // 引入库（编译和运行都需要）
    implementation 'com.google.code.gson:gson:2.10.1'
    
    // 打包进模组 jar
    // 用户下载你的模组时，这个库已经包含在里面了
    // 用户不需要单独下载这个库
    include 'com.google.code.gson:gson:2.10.1'
}
```

**通俗理解**：
- `implementation` = "我需要用这个工具"
- `include` = "把这个工具装进我的工具箱一起带走"

## 特殊配置详解

### Architectury Plugin 配置

```groovy
// 在 Fabric 模块中引用 Common 模块（开发时）
dependencies {
    // developmentFabric 让 Architectury Transformer 在开发时转换 Common 代码
    // 这样你可以在 Fabric 模块中直接使用 Common 的 @ExpectPlatform 方法
    developmentFabric project(path: ':common', configuration: 'namedElements')
}

// transformProductionFabric 用于打包生产版本
// 它会把 Common 代码转换成 Fabric 兼容的格式
```

**什么时候用哪个？**
```
开发时：用 namedElements（方便调试，可以直接看源码）
打包时：用 transformProductionFabric（确保兼容性）
```

### Forge 运行时库

```groovy
// Forge 平台的特殊配置
dependencies {
    // 普通 Java 库
    implementation 'com.example:lib:1.0.0'
    
    // Forge 特有：告诉 Forge 这个库是运行时需要的
    // 为什么？因为 Forge 的类加载器需要知道这个库
    forgeRuntimeLibrary 'com.example:lib:1.0.0'
}
```

**为什么 Forge 需要这个？**
```
Fabric：自动发现所有依赖
Forge：需要手动告诉它哪些库是运行时需要的

就像：
  Fabric 餐厅：自动从仓库拿所有原料
  Forge 餐厅：需要你列一张清单，告诉仓库要拿哪些原料
```

## IDE 配置

### IntelliJ IDEA

1. **安装插件**（可选但推荐）：
   - 打开 Settings → Plugins
   - 搜索 "Architectury" 并安装

2. **导入项目**：
   - File → Open → 选择项目文件夹
   - 等待 Gradle 同步完成（右下角进度条）

3. **生成运行配置**：
   ```bash
   # 生成 IntelliJ 运行配置
   ./gradlew genIntellijRuns
   ```
   - 运行后，IDEA 会自动创建 "Minecraft Client" 和 "Minecraft Server" 运行配置

### Visual Studio Code

1. **安装扩展**：
   - 打开 Extensions (Ctrl+Shift+X)
   - 搜索 "Gradle for Java" 并安装

2. **打开项目**：
   - File → Open Folder → 选择项目文件夹

3. **生成运行配置**：
   ```bash
   ./gradlew vscode
   ```

## 常见问题

### Q: 映射选择哪个？

| 映射类型 | 优点 | 缺点 | 推荐度 |
|----------|------|------|--------|
| **Mojang Mappings** | 官方、准确 | 参数名不完整 | ⭐⭐⭐⭐ |
| **ParchmentMC** | 参数名完整、基于官方 | 需要额外配置 | ⭐⭐⭐⭐⭐ |
| **Yarn** | Fabric 社区维护 | 和 Forge 不兼容 | ⭐⭐⭐ |

**推荐**：Mojang Mappings + ParchmentMC（最佳组合）

### Q: Gradle 版本要求？

需要 **Gradle 8.1** 或更高版本。项目生成器会自动配置正确的版本。

查看当前版本：
```bash
./gradlew --version
```

### Q: 如何更新依赖版本？

1. 修改 `gradle.properties` 中的版本号
2. 在 IntelliJ 中点击 "Reload Gradle Project"（刷新图标）
3. 等待同步完成

### Q: 构建失败怎么办？

1. **清理缓存**：`./gradlew clean`
2. **重新生成配置**：`./gradlew cleanIdea genIntellijRuns`
3. **检查网络**：确保能访问 Maven 仓库
4. **查看日志**：错误信息通常会告诉你是哪个依赖出问题

## 配置文件关系图

```
gradle.properties          ← 定义版本号等常量
       ↓
settings.gradle            ← 定义项目结构和插件仓库
       ↓
build.gradle (根目录)       ← 全局配置和子项目统一配置
       ↓
┌──────┼──────┬──────────┐
↓      ↓      ↓          ↓
common  fabric  forge    neoforge
各模块的 build.gradle     ← 模块特定的配置
```

**读取顺序**：
1. Gradle 启动 → 读取 `settings.gradle`
2. 知道有 4 个子项目 → 读取根 `build.gradle`
3. 应用全局配置 → 读取各子项目的 `build.gradle`
4. 开始构建
