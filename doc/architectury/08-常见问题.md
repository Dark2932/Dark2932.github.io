# 常见问题 (FAQ)

本文档解答使用 Architectury 进行 Minecraft 1.21.1 模组开发时的常见问题。

## 安装和配置

### Q: 如何安装 Architectury？

**A:** 推荐使用项目生成器（最简单的方式）：

1. 访问 [https://generate.architectury.dev](https://generate.architectury.dev/)
2. 选择 Minecraft 1.21.1
3. 填写模组信息（ID、名称、包名）
4. 点击生成并下载
5. 用 IntelliJ IDEA 打开下载的文件夹
6. 等待 Gradle 同步完成

### Q: 需要什么 Java 版本？

**A:** Minecraft 1.21.1 需要 **Java 17** 或更高版本。

> 💡 不确定自己的 Java 版本？在终端输入 `java -version` 查看。

### Q: 支持哪些 IDE？

**A:** 官方支持 **IntelliJ IDEA**（强烈推荐）和 **Visual Studio Code**。

> 💡 如果你是新手，建议直接用 IntelliJ IDEA Community Edition（免费）。

### Q: 如何选择映射（Mappings）？

**A:** 推荐使用 **Mojang 官方映射 + ParchmentMC**（提供更好的参数名）：

```groovy
mappings loom.layered() {
    officialMojangMappings()
    parchment("org.parchmentmc.data:parchment-${minecraft_version}:2024.11.17@zip")
}
```

**通俗理解**：映射就是把 Minecraft 的"加密代码"翻译成人能看懂的名字。

### Q: Gradle 版本要求？

**A:** 需要 **Gradle 8.1** 或更高版本。项目生成器会自动配置正确的版本。

## 项目结构

### Q: 为什么需要多个模块（common/fabric/forge）？

**A:** 这样你可以把代码分成两部分：

- **common**（80-90%的代码）：所有平台共享的代码
- **fabric/forge/neoforge**（5-10%的代码）：各平台特有的小部分代码

**好处**：你只写一次核心代码，Architectury 帮你适配所有平台。

### Q: 可以只支持一个平台吗？

**A:** 可以，但不推荐。如果你只想支持一个平台，直接用那个平台的开发工具会更简单。Architectury 的价值在于"一次开发，多平台运行"。

### Q: 我的代码应该放在哪个模块？

**A:** 简单规则：

| 代码类型 | 放在哪里 |
|----------|----------|
| 物品、方块、实体的逻辑 | common |
| 事件监听 | common |
| 网络消息 | common |
| 配置文件 | common |
| 模组入口点（Main类） | common + 各平台 |
| 平台特定的 API 调用 | 各平台模块 |
| Mixin（公共） | common |
| Mixin（平台特定） | 各平台模块 |

## 注册

### Q: 为什么使用 DeferredRegister？

**A:** 因为 Fabric 和 Forge 的注册方式不同。DeferredRegister 是 Architectury 提供的统一方式，帮你处理平台差异。

**通俗理解**：DeferredRegister 就像"代办服务"，你填好表格交给它，它帮你搞定所有平台的注册流程。

### Q: 何时调用 register()？

**A:** 在模组初始化时调用：

```java
public class YourMod {
    public static void init() {
        ModTabs.register();     // 先注册标签
        ModItems.register();    // 再注册物品
        ModBlocks.register();   // 然后方块
        ModEntities.register(); // 最后实体
    }
}
```

### Q: RegistrySupplier 是什么？

**A:** `RegistrySupplier<T>` 是注册成功后的"凭证"。你不能直接拿到注册的对象，因为注册可能还没完成。用 `.get()` 方法来获取实际对象。

```java
// 定义（此时还没注册）
public static final RegistrySupplier<Item> RUBY = 
    ITEMS.register("ruby", () -> new Item(new Item.Properties()));

// 使用（注册完成后才能 .get()）
Item ruby = RUBY.get();  // 获取真实的 Item 对象
```

## 事件

### Q: 事件返回值是什么意思？

**A:** 

| 返回值 | 通俗解释 |
|--------|----------|
| `EventResult.pass()` | "我只是看看，不干预" → 事件继续传播 |
| `EventResult.interruptTrue()` | "我处理好了！" → 阻止后续处理器 |
| `EventResult.interruptFalse()` | "我阻止了这件事！" → 阻止事件发生 |

### Q: 为什么我的事件处理器没有执行？

**A:** 检查以下常见原因：

1. **没有注册事件**：确保在初始化时调用了注册代码
2. **返回值阻止了传播**：前面的处理器返回了 `interruptFalse()`
3. **注册时机不对**：事件注册应该在初始化阶段
4. **线程问题**：某些事件只在特定线程触发

## 网络

### Q: 为什么需要网络通信？

**A:** Minecraft 有客户端（玩家的电脑）和服务端（服务器），它们需要"对话"：

```
玩家点击按钮 → 客户端发消息 → 服务端处理 → 服务端返回结果 → 客户端显示
```

没有网络通信，客户端和服务端就无法交流。

### Q: 为什么网络回调需要 queue()？

**A:** 因为网络数据包可能在"后台线程"处理，但修改游戏世界必须在"主线程"。

```java
// ❌ 危险：可能在后台线程执行
ctx -> {
    level.setBlockAndUpdate(pos, state);  // 可能崩溃！
}

// ✅ 安全：确保在主线程执行
ctx -> {
    ctx.queue(() -> level.setBlockAndUpdate(pos, state));
}
```

**通俗理解**：就像你不能在开车时同时修车，得把车停下来（切到主线程）再修。

## @ExpectPlatform

### Q: @ExpectPlatform 的命名规则是什么？

**A:** 必须严格遵守：

```
声明位置：com.example.platform.Helper
实现位置：com.example.platform.fabric.HelperImpl  ✅
实现位置：com.example.platform.forge.HelperImpl    ✅
实现位置：com.example.platform.PlatformHelper      ❌（包名不对）
实现位置：com.example.fabric.HelperImpl            ❌（包名层级不对）
```

**规则**：
- 包名 = 声明包名 + `.平台名`
- 类名 = 声明类名 + `Impl`

### Q: 可以用于实例方法吗？

**A:** 不可以！`@ExpectPlatform` 只能用于 `static` 方法。

## Mixin

### Q: Mixin 是什么？

**A:** Mixin 让你"偷偷修改"Minecraft 的代码，而不需要直接改源文件。

**通俗理解**：就像在不拆房子的情况下，偷偷在某个房间加一个插座。

### Q: 如何使用 Mixin？

**A:** 三步走：

1. 创建 Mixin 配置 JSON（告诉游戏"我要改哪些类"）
2. 创建 Mixin 类（写具体的修改逻辑）
3. 确保配置文件在正确的位置

### Q: 可以跨模块使用 Mixin 吗？

**A:** 不可以。Mixin 必须放在对应的模块：

- 公共 Mixin → common 模块
- Fabric Mixin → fabric 模块
- Forge Mixin → forge 模块

## 构建和发布

### Q: 如何构建所有平台？

**A:** 

```bash
./gradlew build
```

构建产物在各模块的 `build/libs/` 目录下：

```
fabric/build/libs/yourmod-fabric-1.0.0.jar
forge/build/libs/yourmod-forge-1.0.0.jar
neoforge/build/libs/yourmod-neoforge-1.0.0.jar
```

### Q: 如何测试模组？

**A:** 

```bash
# 启动 Fabric 测试客户端（像玩游戏一样）
./gradlew :fabric:runClient

# 启动 Forge 测试客户端
./gradlew :forge:runClient
```

### Q: Gradle 同步失败怎么办？

**A:** 试试以下方法：

1. **检查网络**：确保能访问 Maven 仓库
2. **使用 VPN**：某些地区可能需要
3. **清理缓存**：在 IntelliJ 中点击 File → Invalidate Caches → Restart
4. **重新生成**：删除 `.gradle` 文件夹，重新打开项目

## 依赖

### Q: implementation 和 modImplementation 有什么区别？

**A:** 

| 配置 | 用途 |
|------|------|
| `implementation` | 普通的 Java 库 |
| `modImplementation` | Minecraft 模组（会自动处理映射） |
| `include` | 打包进你的模组 jar（用户不需要单独安装） |

### Q: Forge 的 forgeRuntimeLibrary 是什么？

**A:** Forge 平台需要手动把非模组库加到运行时路径：

```groovy
dependencies {
    implementation 'com.example:lib:1.0.0'
    forgeRuntimeLibrary 'com.example:lib:1.0.0'  // Forge 特有
}
```

## 性能

### Q: Architectury 会影响游戏性能吗？

**A:** 几乎不影响。Architectury 主要在编译时做代码转换，运行时开销极小。

### Q: 如何优化模组性能？

**A:** 

1. 避免在事件处理器中创建新对象
2. 缓存计算结果
3. 避免不必要的网络数据包
4. 使用延迟加载

## 调试

### Q: 常见错误及解决方法？

**A:** 

| 错误 | 原因 | 解决方法 |
|------|------|----------|
| `NoClassDefFoundError` | 使用了平台特定 API | 用 @ExpectPlatform 替代 |
| `MixinApplyError` | Mixin 目标方法名错 | 检查映射，确认方法名 |
| `NullPointerException` | 注册顺序问题 | 确保先注册再使用 |
| 构建失败 | 依赖版本冲突 | 检查版本兼容性 |

### Q: 如何启用调试日志？

**A:** 在 build.gradle 中：

```groovy
loom {
    debugLog = true
}
```
