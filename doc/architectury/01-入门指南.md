# Architectury 入门指南

本文档为 Minecraft 1.21.1 版本的 Architectury 模组开发提供入门指导。

## 什么是 Architectury？

### 一句话解释

**Architectury = "写一次代码，同时在 Fabric、Forge、NeoForge 上运行"**

### 生活化比喻

想象你要开一家连锁餐厅，需要在不同城市（Fabric、Forge、NeoForge）开店：

| 概念 | 比喻 |
|------|------|
| **Architectury API** | 统一的菜单和配方，让所有分店做出相同的菜品 |
| **Common 模块** | 总部研发的核心菜品和标准流程 |
| **Fabric/Forge 模块** | 各分店根据当地口味做的微调 |
| **Gradle** | 自动化厨房管理系统，帮你管理食材和流程 |
| **Mappings** | 菜品名称翻译表，让不同城市的员工看懂配方 |

### 为什么需要 Architectury？

**没有 Architectury 时**：你需要为每个平台写一套完整的代码，就像为每个城市单独研发菜单。

**有 Architectury 时**：你写一次核心代码，Architectury 帮你自动适配不同平台，就像连锁餐厅的标准化流程。

## 环境要求

在开始之前，确保你的电脑上安装了以下软件：

| 软件 | 版本要求 | 作用 | 下载地址 |
|------|----------|------|----------|
| **Java** | JDK 17+ | 运行 Minecraft 和编译代码 | [Adoptium](https://adoptium.net/) |
| **IntelliJ IDEA** | 最新版 | 写代码的工具（推荐） | [JetBrains](https://www.jetbrains.com/idea/) |
| **Git** | 最新版 | 版本管理（可选但推荐） | [Git](https://git-scm.com/) |

> 💡 **提示**：如果你用 VS Code 也可以，但 IntelliJ IDEA 对 Minecraft 模组开发支持更好。

## 快速开始

### 方法一：使用项目生成器（推荐新手）

这是最简单的方式，就像点外卖一样方便：

1. **打开网站**：访问 [https://generate.architectury.dev](https://generate.architectury.dev/)

2. **填写信息**：
   ```
   Minecraft Version: 1.21.1        ← 选择游戏版本
   Mod ID: myawesomemod             ← 你的模组ID（全小写，无空格）
   Mod Name: My Awesome Mod         ← 模组显示名称
   Package Name: com.yourname.mod   ← Java包名（像你的公司域名倒着写）
   ```

3. **选择平台**：
   - ☑ Fabric      ← 最流行的平台
   - ☑ Forge       ← 老牌平台
   - ☑ NeoForge    ← Forge 的新版本

4. **点击生成并下载**

5. **在 IntelliJ IDEA 中打开项目**：
   - File → Open → 选择下载的文件夹
   - 等待 Gradle 同步完成（右下角进度条）

### 方法二：手动配置（适合进阶用户）

#### 理解项目结构

```
your-mod/
├── common/          ← 【公共代码】你写的大部分代码放这里
│   └── src/main/java/
│       └── com/yourname/mod/
│           ├── YourMod.java      ← 模组主类
│           └── init/
│               └── ModItems.java ← 物品注册
│
├── fabric/          ← 【Fabric平台】Fabric特有的代码
│   └── src/main/java/
│       └── com/yourname/mod/fabric/
│           └── YourModFabric.java
│
├── forge/           ← 【Forge平台】Forge特有的代码
│   └── src/main/java/
│       └── com/yourname/mod/forge/
│           └── YourModForge.java
│
├── neoforge/        ← 【NeoForge平台】NeoForge特有的代码
├── build.gradle     ← 【构建脚本】告诉Gradle怎么编译你的代码
├── settings.gradle  ← 【项目设置】告诉Gradle有哪些子项目
└── gradle.properties ← 【配置文件】存放版本号等配置
```

**通俗理解**：
- `common` 就像餐厅总部，研发所有分店通用的菜品
- `fabric/forge/neoforge` 就像各地分店，根据当地口味做微调
- `build.gradle` 就像厨房操作手册，告诉系统怎么准备食材

#### Gradle 文件详解

**settings.gradle** - "项目有哪些部分组成"

```groovy
// 这个文件告诉Gradle：我的项目由哪些子项目组成
include('common', 'fabric', 'forge', 'neoforge')

// 就像说：我的连锁餐厅有总部、上海店、北京店、广州店
```

**build.gradle (根目录)** - "全局配置"

```groovy
plugins {
    // 加载 Architectury 插件，这是让多平台开发成为可能的核心工具
    id "architectury-plugin" version "3.4-SNAPSHOT"
    
    // 加载 Loom 插件（暂时不启用，等子项目自己决定用不用）
    id "dev.architectury.loom" version "1.7-SNAPSHOT" apply false
}

// 告诉 Architectury：我们要为 Minecraft 1.21.1 开发
architectury {
    minecraft = rootProject.minecraft_version  // 版本号在 gradle.properties 里定义
}

// 对所有子项目（common, fabric, forge, neoforge）的统一配置
subprojects {
    apply plugin: "java"                  // 使用 Java 语言
    apply plugin: "architectury-plugin"   // 使用 Architectury
    apply plugin: "maven-publish"         // 可以发布到 Maven 仓库（可选）
    
    // 设置项目信息
    version = rootProject.mod_version      // 模组版本，如 "1.0.0"
    group = rootProject.maven_group        // 组织名，如 "com.yourname"
    
    // 配置仓库（去哪里找依赖库）
    repositories {
        maven { url = 'https://maven.parchmentmc.org' }  // ParchmentMC 映射库
    }
}
```

**gradle.properties** - "配置常量"

```properties
# 就像一个配置文件，存放所有可变的值
# 这样改版本号时只需要改这一个地方

# Minecraft 和各平台版本
minecraft_version=1.21.1
fabric_version=0.16.0
forge_version=52.0.16
neoforge_version=21.1.77

# 你的模组信息
mod_version=1.0.0
maven_group=com.yourname
archives_base_name=yourmod
```

#### Common 模块的 build.gradle 详解

```groovy
plugins {
    id "dev.architectury.loom"  // 启用 Loom 插件，它帮我们处理 Minecraft 开发的复杂性
}

// Loom 的一些设置
loom {
    silentMojangMappingsLicense()  // 静默 Mojang 映射的许可提示（避免每次构建都问你）
}

// 依赖项 = 你的项目需要哪些"库"才能编译运行
dependencies {
    // Minecraft 本体 - 这是必须的
    minecraft "com.mojang:minecraft:1.21.1"
    
    // 映射文件 - 把 Minecraft 的混淆代码翻译成可读的名字
    // 比如把 "a.method()" 翻译成 "Player.tick()"
    mappings loom.officialMojangMappings()  // 使用官方映射
    
    // Fabric Loader - Fabric 平台的加载器
    // compileOnly 表示"编译时需要，运行时不需要"（因为运行时平台会提供）
    compileOnly "net.fabricmc:fabric-loader:0.16.9"
}
```

**什么是"映射"（Mappings）？**

```
Minecraft 原版代码是混淆的（像加密一样）：
    class a {
        void b() { ... }  ← 这是什么鬼？
    }

映射文件把它翻译成人能看懂的：
    class Player {
        void tick() { ... }  ← 原来是玩家的tick方法！
    }
```

## 核心概念速查表

| 术语 | 通俗解释 |
|------|----------|
| **Gradle** | 自动化构建工具，帮你编译、打包、管理依赖 |
| **build.gradle** | 告诉 Gradle "怎么构建我的项目"的脚本 |
| **plugins** | Gradle 的功能扩展，像手机装 App |
| **dependencies** | 你的代码需要用到的第三方库 |
| **implementation** | "我需要这个库，编译和运行都要" |
| **compileOnly** | "我只需要编译时用一下，运行时不用" |
| **modImplementation** | "这是一个模组依赖，需要特殊处理" |
| **Mappings** | Minecraft 混淆代码的翻译表 |
| **Fabric/Forge/NeoForge** | Minecraft 的不同模组加载器平台 |
| **Common 模块** | 放所有平台共享代码的地方 |
| **API** | Application Programming Interface，别人提供给你用的功能 |

## 常见问题

### Q: 我应该选 Fabric 还是 Forge？

**A**: 建议都支持！用 Architectury 的目的就是一次开发，多平台运行。

### Q: Gradle 同步失败怎么办？

**A**: 
1. 检查网络连接
2. 尝试使用 VPN 或镜像源
3. 在 IntelliJ 中点击 File → Invalidate Caches → Restart

### Q: 我需要学 Gradle 吗？

**A**: 基础使用不需要深入学习，照着模板改就行。遇到问题时再查文档。
