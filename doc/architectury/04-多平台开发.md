# 多平台开发

本文档介绍如何使用 Architectury 进行多平台模组开发，适用于 Minecraft 1.21.1 版本。

## 理解多平台开发

### 生活化比喻

多平台开发就像开连锁奶茶店：

```
你研发了一款新奶茶（你的模组），想在北京、上海、广州都开店：

Without Architectury：
  - 北京店：用北京的配方重新写一遍
  - 上海店：用上海的配方重新写一遍
  - 广州店：用广州的配方重新写一遍
  → 同一件事做三遍，累死了！

With Architectury：
  - 总部（common）：研发核心配方
  - 各分店：只负责本地化微调（比如北京加冰多一点）
  → 核心代码只写一次！
```

### 代码分布比例

```
┌─────────────────────────────────────┐
│  common（80-90% 的代码）              │
│  物品、方块、实体、事件、网络等         │
├───────────┬───────────┬─────────────┤
│ fabric    │ forge     │ neoforge    │
│ （5-10%）  │ （5-10%） │ （5-10%）   │
│ 平台入口   │ 平台入口   │ 平台入口    │
│ 少量特有代码│ 少量特有代码│ 少量特有代码 │
└───────────┴───────────┴─────────────┘
```

```
your-mod/

```

## 各模块详解

### Common 模块（公共代码）

这里是你的"核心配方"，不能包含任何平台特定的代码。

```java
// ✅ 可以用的：Minecraft 原版 API + Architectury API
import net.minecraft.world.item.Item;
import dev.architectury.registry.registries.DeferredRegister;

// ❌ 不能用的：平台特定 API
import net.fabricmc.loader.api.FabricLoader;  // Fabric 专属！
import net.minecraftforge.fml.ModList;        // Forge 专属！
```

**模组主类（Common）**：

```java
package com.yourname.yourmod;

public class YourMod {
    public static final String MOD_ID = "yourmod";
    
    // 这个方法在所有平台上都会被调用
    public static void init() {
        ModItems.register();     // 注册物品
        ModBlocks.register();    // 注册方块
        ModEntities.register();  // 注册实体
        ModTabs.register();      // 注册创意标签
    }
}
```

**注册类示例（Common）**：

```java
public class ModItems {
    public static final DeferredRegister<Item> ITEMS = 
        DeferredRegister.create(MOD_ID, Registries.ITEM);
    
    public static final RegistrySupplier<Item> RUBY = 
        ITEMS.register("ruby", 
            () -> new Item(new Item.Properties().arch$tab(ModTabs.GEMS_TAB)));
    
    public static final RegistrySupplier<Item> RUBY_SPAWN_EGG = 
        ITEMS.register("ruby_spawn_egg", 
            () -> new ArchitecturySpawnEggItem(
                ModEntities.RUBY_GOLEM,
                0xFF0000,   // 主颜色（红色）
                0x00FF00,   // 副颜色（绿色）
                new Item.Properties().arch$tab(ModTabs.GEMS_TAB)));
    
    public static void register() {
        ITEMS.register();
    }
}
```

### Fabric 模块（分店适配）

Fabric 分店只做两件事：启动模组 + 处理平台差异。

```java
package com.yourname.yourmod.fabric;

import com.yourname.yourmod.YourMod;
import net.fabricmc.api.ModInitializer;

public class YourModFabric implements ModInitializer {
    @Override
    public void onInitialize() {
        // 调用总部的初始化代码
        YourMod.init();
        
        // Fabric 特有的初始化（比如注册实体属性）
        FabricDefaultAttributeRegistry.register(
            ModEntities.RUBY_GOLEM.get(),
            RubyGolem.createAttributes());
    }
}
```

**Fabric 的"营业执照"（fabric.mod.json）**：

```json
{
  "schemaVersion": 1,
  "id": "yourmod",
  "version": "${version}",
  "name": "Your Mod",
  "entrypoints": {
    "main": ["com.yourname.yourmod.fabric.YourModFabric"]
  },
  "depends": {
    "fabricloader": ">=0.16.0",
    "minecraft": "~1.21.1",
    "java": ">=17"
  }
}
```

**通俗理解**：`fabric.mod.json` 就像分店的"开业许可证"，告诉 Fabric 平台"我的店在哪里，入口在哪"。

### Forge 模块（分店适配）

```java
package com.yourname.yourmod.forge;

import com.yourname.yourmod.YourMod;
import dev.architectury.platform.forge.EventBuses;
import net.minecraftforge.fml.common.Mod;
import net.minecraftforge.fml.javafmlmod.FMLJavaModLoadingContext;

@Mod(YourMod.MOD_ID)  // 这个注解告诉 Forge "我是一个模组"
public class YourModForge {
    public YourModForge() {
        // Forge 特有的一步：告诉 Architectury 模组事件总线在哪
        // 就像告诉代办公司"我的营业执照在哪个柜台办的"
        EventBuses.registerModEventBus(YourMod.MOD_ID, 
            FMLJavaModLoadingContext.get().getModEventBus());
        
        // 调用总部的初始化代码
        YourMod.init();
    }
}
```

**Forge 的"营业执照"（mods.toml）**：

```toml
modLoader = "javafml"
loaderVersion = "[52,)"
license = "MIT"

[[mods]]
modId = "yourmod"
version = "${version}"
displayName = "Your Mod"

[[dependencies.yourmod]]
modId = "minecraft"
mandatory = true
versionRange = "[1.21.1,1.22)"
```

### NeoForge 模块（分店适配）

NeoForge 是 Forge 的"升级版"，代码很相似但有一些改进：

```java
package com.yourname.yourmod.neoforge;

import com.yourname.yourmod.YourMod;
import dev.architectury.platform.neoforge.EventBuses;
import net.neoforged.bus.api.IEventBus;
import net.neoforged.fml.common.Mod;

@Mod(YourMod.MOD_ID)
public class YourModNeoForge {
    // NeoForge 改进了：事件总线直接通过构造函数参数传入
    // 不再需要 FMLJavaModLoadingContext（更简洁了！）
    public YourModNeoForge(IEventBus eventBus) {
        EventBuses.registerModEventBus(YourMod.MOD_ID, eventBus);
        YourMod.init();
    }
}
```

## @ExpectPlatform 注解详解

### 一句话解释

**@ExpectPlatform = "在公共代码里声明一个'空壳'，让每个平台自己填上'真正的实现'"**

### 生活化比喻

想象你在总部制定了一条规则："各分店需要提供'获取当地天气'的功能"。

```
总部（common）说：我需要一个能获取天气的功能，但我自己不知道怎么获取
  ↓
北京分店（fabric）：我用天气局API获取
上海分店（forge）：我用自己的气象站获取
广州分店（neoforge）：我用另一个气象API获取
```

### 实际代码

**第1步：在 Common 中声明"空壳"**

```java
package com.yourname.yourmod.platform;

import dev.architectury.injectables.annotations.ExpectPlatform;
import java.io.File;

public class PlatformHelper {
    // 这个方法的"内容"会在运行时被替换成平台特定的实现
    // 所以写 throw new AssertionError() 就行，表示"不应该运行到这里"
    @ExpectPlatform
    public static File getConfigDirectory() {
        throw new AssertionError();
    }
    
    @ExpectPlatform
    public static boolean isModLoaded(String modId) {
        throw new AssertionError();
    }
}
```

**第2步：在 Fabric 中实现**

```java
// 包名必须以 .fabric 结尾！类名必须以 Impl 结尾！
package com.yourname.yourmod.platform.fabric;

import net.fabricmc.loader.api.FabricLoader;
import java.io.File;

public class PlatformHelperImpl {
    // 方法签名必须和声明一模一样
    public static File getConfigDirectory() {
        return FabricLoader.getInstance().getConfigDir().toFile();
    }
    
    public static boolean isModLoaded(String modId) {
        return FabricLoader.getInstance().isModLoaded(modId);
    }
}
```

**第3步：在 Forge 中实现**

```java
// 包名必须以 .forge 结尾！
package com.yourname.yourmod.platform.forge;

import net.minecraftforge.fml.ModList;
import net.minecraftforge.fml.loading.FMLPaths;
import java.io.File;

public class PlatformHelperImpl {
    public static File getConfigDirectory() {
        return FMLPaths.CONFIGDIR.get().toFile();
    }
    
    public static boolean isModLoaded(String modId) {
        return ModList.get().isLoaded(modId);
    }
}
```

### 命名规则速记表

```
声明：com.yourname.platform.PlatformHelper
       ↓
实现：com.yourname.platform.fabric.PlatformHelperImpl   ✅
实现：com.yourname.platform.PlatformHelperFabric         ❌
实现：com.yourname.fabric.PlatformHelperImpl             ❌
```

**规则**：
- 包名 = 声明包名 + `.平台名`（`.fabric`、`.forge`、`.neoforge`）
- 类名 = 声明类名 + `Impl`

## 构建和测试

### 常用命令

```bash
# 构建所有平台的模组
./gradlew build

# 只构建 Fabric 版本
./gradlew :fabric:build

# 只构建 Forge 版本
./gradlew :forge:build

# 只构建 NeoForge 版本
./gradlew :neoforge:build

# 启动 Fabric 测试客户端（像玩游戏一样测试你的模组）
./gradlew :fabric:runClient

# 启动 Forge 测试客户端
./gradlew :forge:runClient

# 生成 IntelliJ IDEA 运行配置
./gradlew genIntellijRuns
```

### 构建产物在哪里？

```
fabric/build/libs/yourmod-fabric-1.0.0.jar   ← 发给 Fabric 用户
forge/build/libs/yourmod-forge-1.0.0.jar     ← 发给 Forge 用户
neoforge/build/libs/yourmod-neoforge-1.0.0.jar ← 发给 NeoForge 用户
```

## 代码组织建议

### 推荐的包结构

```
com.yourname.yourmod/
├── YourMod.java              ← 主类，只做初始化
├── init/                     ← 所有注册代码集中在这里
│   ├── ModItems.java
│   ├── ModBlocks.java
│   ├── ModEntities.java
│   └── ModTabs.java
├── item/                     ← 物品的自定义逻辑
├── block/                    ← 方块的自定义逻辑
├── entity/                   ← 实体的自定义逻辑
├── network/                  ← 网络消息
├── event/                    ← 事件处理器
├── config/                   ← 配置文件
├── util/                     ← 工具类
└── platform/                 ← 平台抽象
    ├── PlatformHelper.java        ← @ExpectPlatform 声明
    ├── fabric/
    │   └── PlatformHelperImpl.java
    └── forge/
        └── PlatformHelperImpl.java
```

**通俗理解**：
- `init/` = 注册办公室（所有"开业登记"都集中在这里）
- `item/`、`block/` = 研发部门（负责具体功能的开发）
- `platform/` = 适配部门（处理不同平台的差异）
